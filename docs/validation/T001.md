# Validation T001 · Modèle et canevas persisté

Date : 10 septembre 2026. Environnement : macOS arm64, Node.js 22.14.0, SQLite 3.47.2, Chromium Playwright 153.0.8010.12.

## Résultat

La première tranche relie une demande écrite synthétique à une proposition structurée, à son application transactionnelle et à une carte persistée. L'utilisateur peut écarter la proposition, renommer ou déplacer une tâche, recharger l'application, consulter l'historique et annuler la dernière modification. Une commande obsolète ou invalide ne remplace pas la carte courante.

## Vérifications exécutées

- `npm test` : 18 tests d'intégration consolidés réussis, dont 16 couvrent T001.
- `npm run test:e2e` : build TypeScript/Vite réussi puis 6 parcours Chromium réussis.
- `npm run format:check` : format des sources contrôlé.
- Contrôle visuel sur `http://127.0.0.1:3100` : titre et canevas visibles, aucune erreur JavaScript remontée.
- Contrôle HTTP local : `GET /api/health` a répondu `{"status":"ok","mode":"synthetic-local"}`.

Les journaux complets sont conservés dans `t001-integration.log` et `t001-browser.log`. La capture `processia-studio.png` illustre la carte de départ. Ils contiennent uniquement des données de test synthétiques.

## Limites

Cette preuve concerne T001, avec une session consultant locale et un dossier synthétique. Elle ne valide pas l'identité du pilote, la séparation privé/partagé, les invitations, MCP, la voix, la qualité d'un fournisseur IA, BPMN, les exports ou le diagnostic. Les six tests navigateur démontrent les parcours, sans constituer une mesure NFR de performance ou d'accessibilité complète.
